
# Diabetes Risk ML

Проект машинного обучения для прогнозирования риска развития сахарного диабета на основе Pima Indians Diabetes Database.

Разработан в рамках курсовой работы по машинному обучению и практических работ по дисциплине «Выбор и построение стека технологий разработки сервисов ИИ в здравоохранении».

Проект демонстрирует полный цикл работы с ML-моделью: подготовку данных, обучение, проведение воспроизводимых экспериментов, оценку качества, тестирование и получение прогнозов.

## Возможности

- Подготовка данных и создание дополнительных признаков.
- Версионирование данных с помощью DVC.
- Управление параметрами обучения через YAML.
- Обучение модели LightGBM.
- Отслеживание экспериментов и метрик в MLflow.
- Логирование с использованием Python logging.
- Проверка качества кода через Ruff.
- Автоматическое тестирование с использованием pytest.
- Сохранение модели и объектов предобработки.
- Получение прогнозов для новых пациентов.
- Автоматическое сохранение результатов в JSON.

## Требования

- Python 3.10–3.12.
- uv для управления зависимостями.
- Git.
- Windows или Linux.
- OpenMP для запуска LightGBM в Linux.

Для Ubuntu/Debian:

```bash
sudo apt update
sudo apt install -y libgomp1
```

## Установка зависимостей

Все зависимости указаны в `pyproject.toml`, а их версии зафиксированы в `uv.lock`.

```bash
uv sync
```

Для установки всех групп зависимостей, включая инструменты разработки:

```bash
uv sync --all-groups
```

На Windows при отсутствии команды `uv` в PATH можно использовать:

```powershell
py -m uv sync
```

## Версионирование данных — DVC

Для версионирования используются два набора данных:

- `data/diabetes.csv` — исходный датасет.
- `data/processed/diabetes_processed.csv` — обработанный датасет.

DVC сохраняет информацию о версиях данных в файлах `.dvc`. Эти файлы отслеживаются Git, сами CSV — нет.

В проекте настроено локальное DVC-хранилище. Для его использования на другом компьютере необходимо указать доступный путь к хранилищу.

Основные команды:

```bash
dvc status
dvc pull
dvc push
```

При изменении данных:

```bash
dvc add data/processed/diabetes_processed.csv
dvc push
```

В ходе работы были созданы две версии обработанного датасета:

| Версия | Предобработка |
|---|---|
| V1 | Заполнение пропусков медианами отдельно для каждого класса Outcome |
| V2 | Заполнение пропусков общими медианами без использования Outcome |

Возможность восстановления предыдущей версии была проверена с помощью `dvc checkout`.

## Подготовка данных

Исходный набор данных содержит 768 наблюдений, 8 числовых признаков и целевую переменную `Outcome`.

Для формирования обработанного датасета:

```bash
uv run python src/prepare_data.py
```

Скрипт заменяет некорректные нулевые значения на пропуски, заполняет их медианами и создаёт шесть дополнительных признаков.

Результат сохраняется в:

```text
data/processed/diabetes_processed.csv
```

Размер обработанного датасета — 768 строк и 15 столбцов.

При обучении модели используется исходный датасет. Разделение на обучающую и тестовую выборки выполняется до вычисления медиан и масштабирования. Это предотвращает утечку информации из тестовой выборки.

## Конфигурация обучения — YAML

Параметры обучения вынесены в файл `config.yaml`.

Пример конфигурации лучшего эксперимента:

```yaml
model:
  name: lightgbm
  n_estimators: 300
  learning_rate: 0.03
  num_leaves: 15
  random_state: 42

training:
  test_size: 0.2
  random_state: 42
```

Изменение параметров не требует редактирования исходного кода обучения.

## Обучение модели

Для запуска обучения:

```bash
uv run python src/train.py
```

При обучении выполняются:

1. Загрузка исходного датасета.
2. Разделение на обучающую и тестовую выборки.
3. Замена некорректных нулевых значений.
4. Заполнение пропусков медианами обучающей выборки.
5. Создание дополнительных признаков.
6. Масштабирование StandardScaler.
7. Обучение LightGBM.
8. Вычисление метрик качества.
9. Сохранение результатов эксперимента в MLflow.

Обученные компоненты сохраняются в:

```text
models/lightgbm_diabetes.joblib
models/scaler.joblib
models/imputer.joblib
```

## Отслеживание экспериментов — MLflow

Для хранения информации об экспериментах используется MLflow с локальной базой SQLite.

В MLflow сохраняются:

- гиперпараметры модели;
- размер тестовой выборки и random seed;
- Accuracy, ROC-AUC, Recall и F1-score;
- Git-коммит;
- MD5 исходного датасета;
- использованная конфигурация;
- сохранённые артефакты модели.

Для запуска интерфейса MLflow из корня проекта:

```bash
uv run mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000
```

Адрес интерфейса:

http://127.0.0.1:5000

База `mlflow.db` хранится локально и исключена из Git.

## Сравнение экспериментов

Проведены три эксперимента LightGBM с разными гиперпараметрами при одинаковом разделении данных.

| Параметр / метрика | Эксперимент 1 | Эксперимент 2 | Эксперимент 3 |
|---|---:|---:|---:|
| n_estimators | 100 | 200 | 300 |
| learning_rate | 0.1 | 0.05 | 0.03 |
| num_leaves | 31 | 20 | 15 |
| Accuracy | 0.7532 | 0.7468 | 0.7662 |
| ROC-AUC | 0.8254 | 0.8237 | 0.8333 |
| Recall | 0.6111 | 0.5926 | 0.6296 |
| F1-score | 0.6346 | 0.6214 | 0.6538 |

Лучший результат на тестовой выборке показал эксперимент №3.

Он имеет наибольшие значения всех четырёх метрик, включая ROC-AUC = 0.8333 и Recall = 0.6296.

## Логирование

В `src/train.py` используется стандартный модуль Python `logging`.

Реализованы уровни:

- `INFO` — этапы загрузки данных, обучения и сохранения результатов.
- `WARNING` — обнаружение некорректных нулевых значений и других предупреждений.
- `ERROR` — запись ошибок обучения с трассировкой исключений.

## Проверка качества кода — Ruff

Для статического анализа:

```bash
uv run ruff check src tests
```

Для проверки форматирования:

```bash
uv run ruff format --check src tests
```

Проверки были успешно выполнены без ошибок.

## Получение предсказания

Тестовые входные данные находятся в:

```text
data/sample_patient.json
```

Для получения прогноза:

```bash
uv run python -m src.predict \
  --input data/sample_patient.json \
  --output results
```

В PowerShell:

```powershell
py -m uv run python -m src.predict --input data/sample_patient.json --output results
```

Пример результата для сохранённой модели третьего эксперимента:

```json
{
  "prediction": 1,
  "risk": "Диабет",
  "probability": 0.8669
}
```

Результат сохраняется в:

```text
results/prediction.json
```

## Bash-скрипт

Для запуска прогнозирования в Linux предусмотрен скрипт:

```text
scripts/run.sh
```

Пример запуска:

```bash
bash scripts/run.sh \
  --input data/sample_patient.json \
  --output results
```

Скрипт позволяет задавать входной JSON-файл и каталог результатов.

## Воспроизводимость экспериментов

Воспроизводимость обеспечивается совместным использованием:

- Git — версии исходного кода.
- DVC — версии данных.
- uv и uv.lock — зафиксированные зависимости.
- YAML — параметры обучения.
- MLflow — параметры, метрики и артефакты экспериментов.
- logging — журналирование выполнения.
- Ruff и pytest — контроль качества кода.

Для повторного проведения эксперимента необходимо восстановить соответствующие версии кода и данных, зависимости из `uv.lock` и конфигурацию, затем запустить обучение.

Локальная база MLflow и DVC-хранилище должны быть доступны отдельно. Они не публикуются автоматически вместе с Git-репозиторием.
